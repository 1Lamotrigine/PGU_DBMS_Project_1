# English Quest — Frontend

Клиентское приложение для платформы English Quest, написанное на **Next.js (App Router)**, **TypeScript** и **Tailwind**.

## Страницы (Маршруты)

| Маршрут | Описание |
| --- | --- |
| `/` | Публичный лендинг |
| `/login`, `/register` | Авторизация и регистрация |
| `/calibration` | Вступительное тестирование (калибровка) |
| `/dashboard` | Профиль, очки опыта (XP), уровни и миссии |
| `/missions/[id]` | Обзор миссии (три модуля) |
| `/test/[id]` | Тестовый модуль — 5 вопросов с выбором ответа |
| `/pronounce/[id]` | Модуль произношения (картинка + слово + транскрипция + перевод) |
| `/game/[id]` | Игра "Словарь" — прилетают карточки с картинками, нужно произнести слово на английском |
| `/admin/missions` | Панель преподавателя (доступна только для роли `teacher`) |

Защита маршрутов реализуется через `src/middleware.ts` (проверка наличия JWT + роли `teacher` для раздела `/admin`).
API-клиент (`src/services/api.ts`) автоматически подставляет заголовок `Authorization: Bearer <token>`.

## Дизайн и темы

Интерфейс выполнен в дружелюбном игровом стиле с использованием библиотеки **daisyUI** (плагин для Tailwind) и предлагает две пользовательские темы:

* `eqlight` — белый фон
* `eqdark` — чисто черный фон

В качестве ключевых цветов используются сине-голубой (primary) и фиолетовый (secondary), из которых формируются градиенты (полосы прогресса XP, бейджи, аватары). Переключатель темы расположен в шапке сайта, а выбранная тема сохраняется в `localStorage` (`eq_theme`); по умолчанию используется системная тема ОС. daisyUI устанавливает атрибут `data-theme` для тега `<html>`.

**Анимация и интерактивность:** библиотека `framer-motion` отвечает за анимации появления и переходов, `canvas-confetti` — за праздничный салют из конфетти при успешном прохождении тестов, произношения, игры или калибровки, `react-countup` — за анимированный счетчик XP, а иконки берутся из `lucide-react`.

## Структура уроков

Каждая миссия представляет собой урок из трех частей, где **для каждого модуля предусмотрена отдельная страница** (порог прохождения — 70%).
Модули открываются **строго по очереди — каждый следующий разблокируется после прохождения предыдущего**:

1. **Тест** (`/test/[id]`) — 5 осмысленных вопросов с выбором ответа. Доступен сразу.
2. **Произношение** (`/pronounce/[id]`) — нужно произнести каждое английское слово вслух. Открывается после успешной сдачи теста.
3. **Игра "Словарь"** (`/game/[id]`) — голосовая игра в стиле **Plants vs. Zombies**, реализованная на **Three.js** (плоская 2D-сцена). **Карточки с картинками** летят справа налево в сторону вашей базы; **микрофон остается включенным на протяжении всей игры**, поэтому вам нужно просто **называть английское слово** для каждой картинки, чтобы она исчезла. Если картинка долетает до левого края, вы теряете **1 из 5 жизней** (шкала здоровья). Для победы нужно уничтожить 12 картинок (порог прохождения — 70%).

Каждый модуль завершается **экраном результатов**: при успехе воспроизводится видео `win.mp4` (персонаж Буба), при неудаче — `lose.mp4` (смеющийся кот); оба ролика со звуком. Медиафайлы находятся в директории `frontend/public/media/`.

Изображения слов расположены в `frontend/public/images/` (SVG-иконки); в модуле произношения отображаются картинка, английское слово, его IPA-транскрипция и перевод на русский язык.

На странице `/missions/[id]` отображаются все три модуля с их текущим статусом: иконка замка, номер модуля или галочка при прохождении. В конце каждого модуля есть кнопка для прямого перехода к **следующему модулю** (Тест → Произношение → Игра "Словарь"). Бэкенд строго контролирует порядок прохождения — отправка результатов произношения отклоняется до сдачи теста, а игра — до сдачи произношения.

В обеих голосовых частях используется **Web Speech API** (`SpeechRecognition`) — без обращения к бэкенду и без использования API-ключей. Если браузер не поддерживает эту функцию (например, Firefox), всегда доступен текстовый ввод, а подсчет результатов все равно выполняется на стороне бэкенда.

## Правила начисления XP

* Первое успешное прохождение уровня (миссии) → начисление `xp_reward_first`.
* Повторное прохождение → начисление `xp_reward_repeat`.
* Результат ниже 70% → XP не начисляется.
* После прохождения калибровки все нижестоящие уровни/миссии засчитываются автоматически, а их `xp_reward_first` прибавляются к стартовому балансу XP.

## Запуск

```bash
cd frontend
npm install
cp .env.local.example .env.local   # NEXT_PUBLIC_API_URL=http://localhost:8000/api/v1
npm run dev                         # http://localhost:3000

```

Убедитесь, что бэкенд запущен (см. `english-quest-backend/README.md`).
